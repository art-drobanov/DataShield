# DataShield

[English](README.md) | **Русский**

**DataShield** — кодек прямой коррекции ошибок (FEC) для передачи небольших файлов через ненадёжные
каналы: текстовые пасты, мессенджеры, тела писем, радиоэфир, носители с повреждениями.

Файл превращается в поток маленьких самодостаточных пакетов — 75 байт, в текстовом режиме
ровно 100 символов Base64, одна строка = один пакет. Приёмник восстанавливает файл из
произвольно повреждённого, переставленного, дублированного и многофайлового потока —
результат гарантированно бит-в-бит исходному (проверка SHA-256 из заголовка).

Ограничения: файлы до ~4 МБ ((65 535 − M) · 64 байт с ECC); имена ASCII до 14 знаков
(длиннее сокращаются с «~»). Работа полностью локальна, сеть не нужна.

## Возможности

- **Потери** — стирающий код Рида–Соломона над GF(2^16): при ECC 10% файл восстанавливается
  при потере до 10% секторов (процент настраивается).
- **Произвольный порядок** — накопительный приём без порядка; сектор несёт только свой номер.
- **Повторы** — повторные копии пакетов не вредят, а повышают счётчики подтверждений.
- **Шум** — пакеты опознаются сканированием скользящим окном; ни один байт не считается
  мусором, пока не проверен усечённым SHA-256.
- **Многофайловые потоки** — сектор криптографически привязан к своему заголовку через хеш;
  файлы не перепутываются.
- **Подделки и коллизии** — версии payload со счётчиками подтверждений и перебор комбинаций
  при сборке; исход без совпадения SHA-256 никогда не выдаётся.
- **Тихие повреждения** — сектор формально валиден, а файл не собирается: перебор подмножеств
  томов восстанавливает подозрительные по оставшимся и ECC.
- **Две схемы секторов** — Classic (секторы с номерами) и опциональная VirtualIndex: поле
  номера заменено более длинным хешем (79 против 72 бит запаса от коллизий), для потоков
  до 512 томов.
- **Два формата вывода** — текстовый (Base64, для чатов и писем) и двоичный (сырые пакеты).

## Быстрый старт

Требуется .NET 10 SDK.

```powershell
dotnet build DataShield.slnx -c Release
dotnet test DataShield.slnx                    # 543 теста
dotnet run --project DataShield.GUI -c Release
```

Консоль — файл в FEC-поток и обратно:

```powershell
dotnet run --project DataShield.Console.RU -c Release -- encode photo.jpg --ecc 20
dotnet run --project DataShield.Console.RU -c Release -- decode photo.jpg.DataShield.txt --all --use-name
```

Кодирование пишет `имя.DataShield.txt` (Base64, по умолчанию) или `имя.DataShield.bin`
(`--format bin`) рядом с исходным файлом; при декодировании формат определяется по
расширению, а суффикс отбрасывается из имени результата.

## Интерфейс командной строки

Команды: `help`, `encode <файл>`, `decode <файл>`. Опции допускают длинную и короткую
формы (`--ecc 20` / `-e 20`) и запись `--key=value`:

| Опция             | Применимо к | Значение                                                          |
| ----------------- | ----------- | ----------------------------------------------------------------- |
| `--format`, `-f`  | encode      | `text` (Base64, по умолчанию) или `bin`                           |
| `--ecc`, `-e`     | encode      | избыточность ECC, %; 0..1000 (по умолчанию 10)                    |
| `--header`, `-h`  | encode      | копии заголовка, %; 0..50 (по умолчанию ~3)                       |
| `--scheme`, `-s`  | обе         | `classic` (по умолчанию) или `virtual`                            |
| `--output`, `-o`  | обе         | путь результата                                                  |
| `--quiet`, `-q`   | обе         | без строки прогресса                                             |
| `--all`, `-a`     | decode      | восстановить все файлы потока, а не только наиболее полный        |
| `--use-name`, `-n`| decode      | сохранить под исходным именем из заголовка                        |

Коды возврата: `0` — успех, `1` — ошибка, `2` — неверное использование, `130` — прерывание
по Ctrl+C (текущая фаза завершается корректно).

## Структура репозитория

- `DataShield.Codec.*` — конвейер кодека: формат провода (`Packets`), источники и
  приёмники IO, Base64-фильтр потока, сканер скользящим окном, ядро приёма
  (`StreamProcessor`), RS-адаптер ECC, отчёты/локализация; `DataShield.Codec` — фасад
  над всем этим.
- Приложения и стенды: `DataShield.GUI`, `DataShield.Console` (+ `.RU`/`.EN`),
  `DataShield.Demo`, `DataShield.Console.Demo`, `DataShield.CollisionBench`.
- Тесты: `DataShield.*.Tests` ×8 (юнит-тесты по модулям) + `DataShield.Tests`
  (интеграционные) — всего 543; `DataShield.TestsHarness` — движок повреждений, общий для
  тестов и стендов.
- `docs/` — полная документация; `refs-src/` — немодифицируемые справочные исходники
  RS/SHA.
